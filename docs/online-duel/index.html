Build Plan

How to make online duel actually scale.

This is the honest backend shape for a realtime 1v1 mode that can support large traffic without pretending plain static pages and S3 are enough.

1. Use a realtime game service

  • Do not run live 1v1 state out of S3 or polling-only functions.
  • Use server-authoritative realtime rooms.
  • Best fit: Cloudflare Durable Objects plus WebSockets.
  • Good alternatives: Ably, Pusher, Liveblocks, or Supabase Realtime.

2. Keep game state tiny

  • Store only room id, players, round seed, zoom step, timer, and guesses.
  • Never stream actual screenshots.
  • Broadcast typed state and submitted guesses instead.
  • Use shared signed image URLs from the approved catalog.

3. Matchmaking flow

  • Player enters queue with a short-lived session token.
  • Matchmaker pairs two compatible players.
  • Room server waits until both clients are ready.
  • Round timer starts from the server, not the browser.

4. Fairness rules

  • Both players receive the same seeded image order.
  • The image zooms out every 15 seconds on a server clock.
  • Answers are validated on the server.
  • Earliest valid server timestamp wins the round.

5. Anti-spam and cost control

  • Rate limit queue joins and guesses per IP and per session.
  • Add bot protection before entering matchmaking.
  • Expire inactive rooms aggressively.
  • Cache the approved image manifest outside the room server.

6. Good first release

  • Friend rooms first, random matchmaking second.
  • Best-of-3 matches.
  • Opponent typing and recent guesses only.
  • Reconnection grace period before a forfeit.
Recommended stack

If we actually want this to work for thousands of players, I would build it as: static frontend + approved-image API + realtime room service + lightweight matchmaking queue. The current Netlify/S3 app is great for solo mode, but not enough by itself for honest large-scale live multiplayer.
